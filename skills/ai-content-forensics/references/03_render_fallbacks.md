# Render Fallbacks — PNG generation priority chain

The skill produces 9 carousel visuals as SVG (primary editable), self-contained HTML/CSS (preview), and PNG (publish-ready). The SVG and HTML always ship; PNG depends on the host environment.

## Priority chain

Try paths in order; stop at the first success. Log the chosen path in `logs/fallback_log.md` with the format `| asset_slug | path_used | reason_if_fallback |`.

### 1. `rsvg-convert` (preferred)

The fastest, most reliable path. Single binary, no browser dependency.

```bash
for svg in visuals/assets/*.svg; do
  rsvg-convert -w 1080 -h 1350 "$svg" -o "visuals/previews/$(basename $svg .svg).png"
done
```

Install:
- macOS: `brew install librsvg`
- Linux: `apt install librsvg2-bin` or `dnf install librsvg2-tools`
- Already widely available

### 2. Headless Chrome / playwright / puppeteer

If `rsvg-convert` is missing, use a headless browser to load the HTML at 1080×1350 viewport and screenshot the SVG element.

```bash
# puppeteer one-liner (requires node + puppeteer):
node -e '
const puppeteer = require("puppeteer");
(async () => {
  const b = await puppeteer.launch();
  const p = await b.newPage();
  await p.setViewport({width: 1080, height: 1350});
  for (const f of process.argv.slice(1)) {
    await p.goto("file://" + require("path").resolve(f));
    await p.screenshot({path: f.replace(".html", ".png").replace("/assets/", "/previews/")});
  }
  await b.close();
})();
' visuals/assets/*.html
```

### 3. Chrome MCP screenshot

In Claude Code with Chrome MCP available:

```
for each html file:
  mcp__claude-in-chrome__navigate to file://...
  mcp__claude-in-chrome__resize_window 1080 1350
  mcp__claude-in-chrome__computer screenshot
  save bytes to visuals/previews/{slug}.png
```

Slow (one HTTP request per asset). Use only if 1 and 2 are unavailable.

### 4. SVG-only ship

If no rendering is available, the skill ships SVG + HTML and skips PNG. Note in `logs/fallback_log.md` that PNGs can be regenerated by the operator with any of the above paths. The thread-publishing flow downgrades to "manual screenshot from HTML" — the operator opens each HTML in a browser at 1080×1350 and saves the screen.

## Detection logic

`scripts/visuals.py` checks tool availability in order:

```python
import shutil
for tool in ("rsvg-convert", "node"):
    if shutil.which(tool):
        # use this path
        break
else:
    # fall back to SVG-only
    log_fallback("PNG render unavailable — ship SVG/HTML only")
```

The current canonical implementation only invokes `rsvg-convert` if available; further fallbacks are documented but not auto-invoked. Operators with neither tool should pass `--png-mode skip` to avoid wasted retries.

## Quality assurance

PNG output sanity check:
- File size > 30KB (a 1080×1350 minimalist editorial PNG is typically 80-200KB)
- File size < 5MB (anything larger indicates a render bug — check for accidentally-embedded images)
- ImageMagick `identify` returns exactly `1080x1350` dimensions

If a PNG fails sanity, log it as a render failure and re-render with a different path.
